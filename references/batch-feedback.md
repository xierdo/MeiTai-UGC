# Batch and testing (optional)

Use only when user requests batch planning, spreadsheet fields or performance iteration. Avoid making routine script generation burdensome.

Suggested minimal record: creative_id, SKU, segment, awareness_hypothesis, format, hook, care_logic, CTA, variant_group, changed_variables, asset_ids, generator, duration, prompt_chars, QA_status, date, impressions, 2s/6s view rate (or platform equivalents), CTR, CVR, spend, orders, GMV, ROAS/ROI definition, notes.

Treat variants as hypotheses. If data exists, compare at similar traffic, placement, price, spend and time window where practical. Distinguish attribution and organic/paid performance; report missing denominators and sample size. Never infer winners from creative opinion alone. No universal KPI thresholds; use observed baseline and product economics.

For a new batch: reuse validated audience, product logic and structural blocks; vary one or two meaningful creative inputs. A practical heuristic, adapted from the reviewed source: 0–1 new unvalidated creative variables = conservative, 2 = moderate, 3+ = exploratory. This is performance uncertainty, not legal safety. Without a validated baseline, mark all as exploratory instead of falsely labeling them proven. No fixed allocation unless the user chooses one. After enough comparable data, refine the brief and atom library based on observed behavior.
